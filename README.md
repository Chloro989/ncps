# centurion

小説の添削・発想支援ツール。原稿を読み込み、観点を選び、LLM に論評させ、
出力が本文と食い違っていないか機械的に検査する。

小説生成 (`write`) も含むが試作。詳細は「限界」を参照。

## 特徴

- **依存なしで動作** — 添削系は Python 標準ライブラリのみ。`pip install` 不要
- **バックエンドを選択可能** — llama.cpp / Claude API / transformers / 出力のみ
- **出力を検査** — 存在しない段落番号、本文と食い違う引用、
  原稿を指していない指摘を機械的に検出
- **ローカル完結** — Web UI は `127.0.0.1` のみ待ち受け

## 動作環境

| | |
|---|---|
| Python | 3.8 以上 |
| OS | Windows / macOS / Linux |
| GPU | 不要 (`write` と `--run` のみ必要) |

## インストール

```bash
git clone https://github.com/Chloro989/ncps
cd ncps
python main.py
```

追加パッケージは機能ごとに任意。未インストールならその機能のみ無効になる。

```bash
pip install torch transformers accelerate   # write, --run
pip install fugashi unidic-lite             # --words 形態素
```

## クイックスタート

```bash
# 1. 原稿を manuscripts/ に置く (中身は .gitignore 済み)
# 2. 構造を確認
python main.py read 原稿.txt

# 3. プロンプトを生成して任意のチャットに貼る
python main.py ask 原稿.txt --mode 発想 > prompt.txt

# 4. 得た回答を検査し、添削ファイルを出力
python main.py check answer.txt 原稿.txt --out 添削.txt
```

GUI:

```bash
python main.py web
```

# 使い方

## 原稿の指定

```bash
python main.py read 原稿.txt          # manuscripts/ 内はファイル名のみで可
python main.py read C:\path\to\原稿.txt
python main.py read                   # 省略時はファイル選択ダイアログ
```

Colab ではダイアログの代わりにアップロード UI が開く。
`manuscripts/` の内容は `.gitignore` で除外済み。

対応形式:

- 文字コード: UTF-8 / Shift_JIS / EUC-JP を自動判別
- 章見出し: `# 見出し` / `第一章` / `＊` などの区切り行
- 青空文庫形式: 凡例・底本・ルビ・傍点注記を除去し、題名と著者を抽出
- 段落: 空行区切りと 1 行 1 段落の両方

## 構造の確認

```bash
python main.py read 原稿.txt --size 3000
```

```
「冒頭プロトタイプ 第五稿」
  4533文字 / 1章 / 103段落 / 218文

3000文字ずつに切ると 2塊
  塊0: 0章 段落0〜70 (2977文字)
  塊1: 0章 段落71〜102 (1587文字、うち重なり1段落)

反復 11件
  《反復》「航空研究会」[3]・[71] (隔たり66%・2715文字)
  《主題》「田島」[3]・[4]・[7]・[14]…他4箇所 (隔たり96%・4201文字)
```

- **反復** — 離れた位置で繰り返される稀な語。伏線の候補
- **主題** — 作品全体に分布する語

## 論評の実行

バックエンドは 4 種類。

### 出力のみ (既定)

```bash
python main.py ask 原稿.txt --mode 発想 > prompt.txt
python main.py check answer.txt 原稿.txt --out 添削.txt
```

LLM を呼ばずプロンプトのみ出力する。任意のチャットに貼り付けて使う。

### Claude API

```bash
setx ANTHROPIC_API_KEY "sk-ant-..."     # Windows。設定後に端末を再起動
python main.py ask 原稿.txt --api --out 添削.txt
python main.py ask 原稿.txt --api --all --out 添削.txt   # 全塊を処理
```

API キーは環境変数から読み取るのみ。保存・表示は行わない。

### llama.cpp

AMD GPU で動作する唯一のバックエンド (torch は非対応、llama.cpp は Vulkan 対応)。

```bash
winget install ggml.llamacpp
llama-server --list-devices              # GPU 認識の確認
llama-server -hf LiquidAI/LFM2.5-1.2B-JP-202606-GGUF -ngl 99 -c 16384 --port 8080
```

```bash
python main.py ask 原稿.txt --llama --model LFM2.5-1.2B-JP
```

- `-ngl 99` — 全レイヤーを GPU に配置
- `-c 16384` — コンテキスト長。既定の 4096 では不足する

**制約:** `llama-server` は起動時に読み込んだモデル 1 つのみを提供する。
`--model` はサーバに送信されるが**無視される**ため、記録用のラベルとして機能する。
複数モデルを使う場合はポートを分けてサーバを複数起動する。

`write` の抑圧処理はロジット操作を必要とするため llama.cpp では動作しない。
論評系は抑圧を使わないので影響しない。

### transformers

NVIDIA GPU が必要。

```bash
python main.py ask 原稿.txt --run
python main.py ask 原稿.txt --run --model LiquidAI/LFM2-1.2B
```

`transformers` 5.14 は LFM2 系 (`lfm2` / `lfm2_moe` / `lfm2_vl`) に対応済み。

### 比較

| バックエンド | GPU | 費用 | 備考 |
|---|---|---|---|
| 出力のみ | 不要 | 無料 | 貼り付け先のモデル性能に依存 |
| `--api` | 不要 | 従量 | 最も高品質 |
| `--llama` | AMD 可 / CPU 可 | 無料 | モデル性能に依存 |
| `--run` | NVIDIA | 無料 | モデル性能に依存 |

## 添削ファイル

`--out` で出力。ヘッダに実行条件、本文に段落ごとの指摘が並ぶ。

```
# 原稿名 の添削
# 日付: 2026-08-15 21:56
# モード: 発想
# モデル: claude-sonnet-5 (API)
# 原稿: 5782文字 / 104段落
# 読ませた範囲と観点: 1/1塊 一度きり／固有／分岐 [実測 名前25% …]
# 検証: claude-opus-5 (API) — 6件を残し、8件を捨てた
# 語の取り出し: 正規表現
# 原稿を指している指摘 12/14件 (86%)
# 引用の照合: 14件中 一致12件 / 不一致2件

## 本文と指摘

[58] アパートに帰り、電気もつけずに、私は部屋の真ん中に立っていた。
    × - **段落 [58]**: 「エーマートの前を通った。半分切れた看板が…」
```

| 記号 | 意味 |
|---|---|
| `▸` | 引用が本文と一致。採用可 |
| `×` | 引用が本文と不一致。破棄すべき |

`モデル` 欄はバックエンドにより表記が変わる。

| 実行方法 | 記録 |
|---|---|
| `--api` | `claude-sonnet-5 (API)` |
| `--llama` | `LFM2.5-1.2B-JP (llama.cpp)` |
| `--run` | `Qwen/Qwen2.5-3B-Instruct (手元)` |
| `check` | `不明 (外で解かせた答え)` |
| `check --model NAME` | `NAME (申告)` |

# モードと観点

## モード

| `--mode` | 処理内容 | 制約 |
|---|---|---|
| `発想` | 未着手の可能性を提示させる (既定) | — |
| `査読` | 客観的評価を行わせる | — |
| `接続` | 離れた 2 箇所の関連付けを提案させる | 3000 文字以上 |
| `連想` | 連想を辿り作品に還元させる | — |

`接続` は距離のある 2 点を必要とするため、短編では実行を拒否する。

## 観点の選択

観点は 28 種類 (発想 21 / 査読 13)。既定では原稿を測定し、不足している要素に対応する観点を選ぶ。

```bash
python main.py ask 原稿.txt --survey            # 測定値と選択理由を表示
python main.py ask 原稿.txt --lens 視点,熱量     # 手動指定
python main.py ask 原稿.txt --random-lenses     # ランダム選択
python main.py ask 原稿.txt --lenses 2          # 個数変更 (既定 3)
```

観点はモードによって使えるものが異なる。

| 群 | 観点 | 発想 | 査読 |
|---|---|---|---|
| 構造 | 削除・重心 | ○ | ○ |
| 構造 | 順序・一度きり | ○ | — |
| 逸脱 | 予想・安全・約束事・既視 | ○ | — |
| 視点 | 視点・時制・信頼 | ○ | — |
| 不在 | 分岐・沈黙・欠落 | ○ | — |
| 熱量 | 密度 | ○ | ○ |
| 熱量 | 熱量 | ○ | — |
| 調子 | 調子・笑い・落差 | ○ | ○ |
| 具体 | 固有・感覚 | ○ | — |
| 査読 | 主題・構成・文体・人物・仕掛け・達成・未達 | — | ○ |

**査読モードでは提案型の観点を使わない。** 査読の規則は
「本文に無い要素について述べない」であり、
「書かれなかった道を三つ挙げよ」のような観点と矛盾するため。
`--lens` で明示指定した場合もモード不適合ならエラーになる。

**個数は 3 以下を推奨。** 3B 級モデルでは指示数に反比例して各指示の遵守率が
低下する (禁止語 6 個では有効、8 個では逆効果という測定結果)。
広く見る場合は個数を増やさず `--all` または `--seed` を変えて複数回実行する。

### 測定値

`--survey` で表示される値。すべて 0〜1 に正規化。

| 項目 | 内容 |
|---|---|
| 名前 | 固有名詞を含む段落の割合 |
| 会話 | 会話文の段落の割合 |
| 出来事 | 過去の出来事を 2 文以上含む段落の割合 |
| 感覚 | 使用されている感覚の種類 (音・におい・手触り・温度・光) |
| 一人称 | 一人称代名詞を含む段落の割合 |
| 偏り | 段落長の変動係数 |
| 混在 | ですます体とである体の混在度 |
| 轍 | 常套語 (宇宙・神秘・永遠 等) の密度 |

観点の必要度はこれらから算出する。例: 名前が少なければ【固有】が上昇し、
感覚が揃っていれば【感覚】が下降する。

## 語の抽出方法

反復語検出時の単語分割方法。

```bash
python main.py read 原稿.txt --words 形態素     # fugashi + unidic-lite が必要
```

| 方式 | 依存 | 特性 |
|---|---|---|
| 正規表現 (既定) | なし | 漢字 2 文字以上 / カタカナ 2 文字以上 |
| 形態素 | fugashi, unidic-lite | 1 文字の名詞を検出。複合語が分割される |

既定を正規表現にしている理由は測定結果による。形態素解析に置換すると
検出数が 68 → 178 件に増加し (副詞などのノイズ)、
複合語「虫干し」が「虫 / 干し」に分割され既知の伏線を取りこぼした
(正解率 4/7 → 3/7)。ただし 1 文字名詞が取れる利点はある。

不要と判断した場合は `centurion/connect.py` の `morphological_words` を削除する。

# 出力の検査

LLM 出力は信頼しない前提で設計している。`--api` / `--run` / `--llama` 実行時は
自動、貼り付け運用時は `check` で実行する。

```bash
python main.py check answer.txt 原稿.txt --chunk 1 --out 添削.txt
```

## 検査項目

| 項目 | 検出内容 |
|---|---|
| 錨の数 | 原稿のどの段落も指していない指摘の割合 |
| 段落番号 | 存在しない段落番号への言及 |
| 範囲外 (`--chunk N`) | 入力に含めていない段落への言及 |
| 引用照合 | 段落番号と引用文の不一致、本文に存在しない引用 |

### 錨の数

引用照合は引用を含む指摘しか検査できない。段落を一切指さない出力は
検査を素通りし「不一致 0 件」と表示されてしまう。

実測例: 4 件の指摘がいずれも段落を指さず、本文に存在しない語のみで
構成されていたが、引用照合は「1 件中 一致 1 件」を出力した。

```
原稿を指している指摘 0/4件 (0%)
  半分も原稿を指していない。本文から離れた一般論になっている疑いが強い。
  観点を減らすか、より大きいモデルに解かせること
```

### 引用照合

10 文字以上の鉤括弧のみを照合対象とする。日本語では作中語を
「あっちゃぐり」のように括る用法が一般的で、短い括弧まで照合すると
正当な指摘に `×` が付く (実測で 4 件中 3 件が誤検出)。

実測例 (Qwen2.5-3B):

```
× [58] 引用は [57] の中身: エーマートの前を通った。半分…
× [59] 本文に無い文を引用している: 帰る途中、エーマートの冷蔵庫…
```

段落番号は 18 件すべて実在したが、引用 14 件中 8 件が別段落の内容であり、
うち 3 件は本文に存在しない文だった。
「引用が実在するか確認せよ」とモデルに自己申告させる方式では検出できない。

## 検証 (LLM による再審査)

```bash
python main.py ask 原稿.txt --llama --verify
python main.py ask 原稿.txt --llama --verify --verify-with api
python main.py ask 原稿.txt --api --verify --verify-model claude-opus-5
```

| 引数 | 既定 | 説明 |
|---|---|---|
| `--verify` | — | 出力された指摘を再審査し、通過分のみ残す |
| `--verify-with` | 同一 | 審査側のバックエンド (`api` / `llama` / `run`) |
| `--verify-model` | 同一 | 審査側のモデル |
| `--verify-llama-url` | `--llama-url` と同一 | 審査側の llama-server |

機械的検査では「引用は正しいが判断が誤り」を検出できないため、
別モデルによる再審査を行う。

設計方針:

- **二値判定。** 点数評価は基準が実行ごとに 19pt 変動する測定結果があるため、
  「残す」「捨てる」のみを選択させる
- **反証側に立たせる。** 肯定的評価を求めると全件通過するため、
  欠陥を探す役割を与え、判断に迷う場合は破棄を既定とする
- **別モデルを推奨。** 同一モデルは自身の出力を通過させる傾向がある

破棄基準: 本文に存在しない内容 / 誤読 / 実行不可能な助言 /
代償の未記載 / 他の指摘との重複。

安全機構:

- 全件破棄された場合は元の出力を保持する (審査側の過剰動作を疑う)
- 判定不能だった指摘は破棄せず印を付けて残す
- 判定が 1 件も読み取れない場合は元の出力をそのまま返す

### llama.cpp で別モデルを使う場合

`llama-server` は 1 プロセスにつき 1 モデルのみ提供する。
`--verify-model` に別名を指定してもサーバは無視するため、
**同一 URL を指す限り審査は同じモデルが行う。**

別モデルで審査するにはポートを分けてサーバを 2 つ起動する。

```bash
llama-server -hf LiquidAI/LFM2.5-1.2B-JP-202606-GGUF -ngl 99 --port 8080
llama-server -hf Qwen/Qwen2.5-7B-Instruct-GGUF -ngl 99 --port 8081
```

```bash
python main.py ask 原稿.txt --llama --verify --verify-llama-url http://127.0.0.1:8081/v1/chat/completions
```

同一 URL を指している場合は実行時に警告を出す。

# ブラウザ UI

```bash
python main.py web
python main.py web --port 9000 --no-open
```

`127.0.0.1` のみ待ち受ける。同一ネットワーク上の他ホストからは接続不可。

セキュリティ:

- API キーはサーバ側の環境変数に留まり、ブラウザには送信しない
- 原稿は `manuscripts/` 配下のみアクセス可 (`../` を含むパスは拒否)
- 本文は HTML エスケープしてから描画

タブ構成:

| タブ | 機能 |
|---|---|
| 添削 | 原稿の選択・貼り付け、観点設定、実行、結果表示、添削ファイル出力 |
| 創作 | 小説生成 (試作) |
| チャット | 通常の対話。人格プロンプトの適用可 |

添削タブの左ペインに測定値・観点の必要度・反復語を表示する。
項目名にカーソルを合わせると測定内容が表示される。

# 限界

## 小説生成

「発想の飛躍」は未達成。出力は可読で常套からわずかに外れた文章であり、
飛躍ではない。3 機構を実装・測定していずれも読み手に差を検出できなかった。

実測 112 件の分析:

| 項目 | 割合 |
|---|---|
| 読み手に語りかける | 112/112 (100%) |
| 固有名詞を含む | 2/112 (2%) |
| 過去の出来事を 2 文以上語る | 32/112 (29%) |
| 一文目が「X は〜です」型の一般論 | 47/112 (42%) |

人格設定は「物語だけを愛する」だが 7 割が出来事を語っていない。
原因は書き出しの `そうですね、` と推定 (相槌の後に続く自然な文型は
同意・意見・一般化であり、場面描写ではない)。**未検証**のため
既定は評価時と同じ値のまま。`--prefill` で変更可能。

流動プロンプトの優位性は p=0.108 で有意水準未達。`--fixed-prompt` で戻せる。

## 添削

3B 級モデルでは実用に耐えない。実測:

- 引用 14 件中 8 件が別段落の内容、うち 3 件は本文に存在しない文
- 別の実行では 4 件の指摘がいずれも段落を指さず、本文にない語のみで構成

検査機構はこれらを検出するが、検出できても出力の質は上がらない。
実用には API または 7B 以上のモデルを推奨。

## 接続モード

3000 文字未満の原稿では動作しない。距離のある 2 点が存在しないため。
実測: 太宰治「I can speak」(1949 文字・15 段落) では、
段落間距離 27% と表示された語が実際には 4 段落しか離れておらず、
同一場面の同一人物を指していた。距離の下限を 1500 文字に設定して対処。

## 語の抽出

- 1 文字の語を検出できない (形態素解析未使用時)
- 固有名詞判定は敬称・地名接尾辞・4 文字以上のカタカナによる近似
- 「一度きりの語」は長編でのみ有効 (4500 文字では 221 語が該当)
