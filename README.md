# センチュリオン

小説を書く人に伴走する道具と、文章を保ったまま常套から外れた語りを返す生成AI。

操作はすべて `main.py` から。

| 命令 | すること | モデル |
|---|---|---|
| `read` | 原稿の構造・反復を見る | 不要 |
| `ask` | 原稿を読ませて論評・発想を得る | `--api`/`--run` のときだけ |
| `check` | 答えが本文と食い違っていないか検査する | 不要 |
| `write` | 小説を書かせる | 必要 |
| `test` | 試験を全部走らせる(326件) | 不要 |

---

# 使い方

## 1. 用意する

```bash
git clone https://github.com/Chloro989/ncps
cd ncps
```

原稿を読ませるだけなら、これで動く。`pip install` は要らない。
小説を書かせる (`write`) ときだけ `pip install torch transformers accelerate`。

## 2. 原稿を置く

`manuscripts/` に入れる。**この中身は git に入らない**ので、
未発表の作品を置いても公開リポジトリには出ない。

```bash
python main.py read 第五稿.txt
```

パスを省くと窓が開く。手元のPCならファイル選択、Colab ならアップロード。

```bash
python main.py read
```

## 3. まず原稿を見る

```bash
python main.py read 第五稿.txt
```

```
「冒頭プロトタイプ 第五稿」
  4533文字 / 1章 / 103段落 / 218文

3000文字ずつに切ると 2塊
  塊0: 0章 段落0〜70 (2977文字)
  塊1: 0章 段落71〜102 (1587文字、うち重なり1段落)

反復 11件
  《反復》「航空研究会」[3]・[71] (隔たり66%・2715文字)
  《主題》「田島」[3]・[4]・[7]・[14]…他4箇所 (隔たり96%・4201文字)
```

「反復」は遠く離れて繰り返される稀な語 = 作者がすでに植えた種。
「主題」は作品を貫く背骨。

## 4. 論評させる

道は三つある。**質が要るなら 4-A、無料で済ませたいなら 4-B。**

### 4-A. その場で論評させる (鍵が要る)

```bash
python main.py ask 第五稿.txt --mode 発想 --api --out 添削.txt
```

鍵は一度だけ設定する。この道具は保存も表示もしない。

```bash
setx ANTHROPIC_API_KEY "自分の鍵"        # Windows。設定後に端末を開き直す
```

```python
import os; os.environ['ANTHROPIC_API_KEY'] = '自分の鍵'   # Colab
```

原稿全体を順に読ませるなら `--all`。塊ごとに観点が入れ替わる。

```bash
python main.py ask 第五稿.txt --mode 発想 --api --all --out 添削.txt
```

### 4-B. 問いだけ出して、好きなチャットに貼る (無料)

```bash
python main.py ask 第五稿.txt --mode 発想 > 問い.txt
```

`問い.txt` を Claude なり ChatGPT なりに貼り、答えを `答え.txt` に保存してから

```bash
python main.py check 答え.txt 第五稿.txt --out 添削.txt
```

### 4-C. 手元のモデルで解かせる (無料、質は落ちる)

```bash
python main.py ask 第五稿.txt --mode 発想 --run
python main.py ask 第五稿.txt --mode 発想 --run --model LiquidAI/LFM2-1.2B
```

`--model` には HuggingFace のどのモデル名でも渡せる。
`transformers` 5.14 は LiquidAI の LFM2 系(`lfm2` / `lfm2_moe` / `lfm2_vl`)に
対応済みなので、追加の作業なしで動く。

3B級では**引用14件中8件を取り違えた**実測がある。下の「検査」を必ず通すこと。

## 5. 添削を受け取る

`--out 添削.txt` を付けると、本文の各段落の下にその段落あての指摘が並ぶ。

```
[57] 帰り道、エーマートの前を通った。半分切れた看板が「ー マート」と光っている。

[58] アパートに帰り、電気もつけずに、私は部屋の真ん中に立っていた。
    × - **段落 [58]**: 「エーマートの前を通った。半分切れた看板が…」
```

`×` が付いた指摘は**引用が本文と食い違っている**ので捨てる。
`▸` が付いたものは照合を通っている。

# モードと観点

## モード (`--mode`) — 自分で選ぶ

| モード | 何をさせるか | 向く原稿 |
|---|---|---|
| `発想` | まだ書かれていない先を探させる (既定) | どれでも |
| `査読` | 客観的に評価・査読させる | どれでも |
| `接続` | 遠く離れた二箇所に橋を架けさせる | **3000文字以上** |
| `連想` | 連想を数歩たどって作品へ戻させる | どれでも |

`接続` は遠い二点が要るので短編では断られる。そのときは `発想` を使う。

## 観点 — 既定では原稿を測って選ぶ

観点は18個ある(視点・熱量・削除・分岐・固有・感覚…)。
**既定では原稿を実測して、足りていないところへ問いを向ける。**
感覚描写で埋まった原稿に「感覚を足せ」と言っても意味がないため。

何が測られ、どの観点が選ばれるかを見る:

```bash
python main.py ask 第五稿.txt --survey
```

```
実測
  名前のある人や場所を含む段落        25%
  過去の出来事を2文以上語る段落       27%
  使われている感覚の種類            100%

観点の必要度
   75%  【一度きり】構造
   75%  【固有】具体
   73%  【分岐】不在
   ...
   14%  【感覚】具体          ← 感覚は足りているので選ばれない
```

**観点を自分で決めることもできる。**

```bash
python main.py ask 第五稿.txt --lens 視点,熱量,安全      # 名指しする
python main.py ask 第五稿.txt --random-lenses           # くじ引きに戻す
python main.py ask 第五稿.txt --lenses 5                # 数を変える(既定3)
```

使える観点の名前:

| 群 | 観点 |
|---|---|
| 構造 | 削除・順序・一度きり・重心 |
| 逸脱 | 予想・安全・約束事・既視 |
| 視点 | 視点・時制・信頼 |
| 不在 | 分岐・沈黙・欠落 |
| 熱量 | 熱量・密度 |
| 具体 | 固有・感覚 |

一度に渡すのは2〜3個までにする。**3Bモデルでは指示を増やすと
一つひとつが薄まる**ことを実測している(禁止語6個は効いたが8個では効かなくなった)。
多く見たいなら、数を増やすのではなく `--all` で回すか、種を変えて何度か回す。

## 語の取り出し方 (`--words`)

反復を探すときの語の切り出し。既定は正規表現(漢字2文字以上か
カタカナ2文字以上)で、依存が無く手元だけで動く。

```bash
python main.py read 第五稿.txt --words 形態素     # fugashi + unidic-lite が要る
```

```bash
pip install fugashi unidic-lite
```

**既定を正規表現のままにしている理由。** 参考作品で素直に差し替えて測ると、
反復が68件から178件に膨れ、雑音(しょっちゅう・だんだん・いっぱい)が増え、
`虫干し` が `虫/干し` に割れて**作者の伏線を落とした**。正解は4/7から3/7へ下がる。

一方で拾い物もある。一文字の名詞(鴻・毛・羽)が取れるようになり、
「あっちゃぐり」では `スーパー[8]・[84]・[88]` — **安売りスーパーと
「スーパーエンジニア」の二重**を検出した。

どちらが良いかは原稿による。**比べて要らなければ
`centurion/connect.py` の `morphological_words` ごと消せばよい。**

## 検査 — 答えを鵜呑みにしない

`--api` / `--run` のときは自動で走る。貼って答えを得た場合は `check` で。

```bash
python main.py check 答え.txt 第五稿.txt --chunk 1 --out 添削.txt
```

三つを見る。

| 検査 | 見つかるもの |
|---|---|
| 段落番号の実在 | 存在しない番号への指摘 |
| 渡した範囲 (`--chunk N`) | 読ませていない段落への言及 |
| 引用と本文の照合 | 番号と中身が食い違う指摘、本文に無い文の引用 |

照合するのは**10文字以上の鉤括弧**だけにしてある。日本語は語をそのまま
「あっちゃぐり」のように括るので、短いものまで突き合わせると
**正しい指摘に × が付く**。実際に作中語を括った指摘3件へ誤って × を付けていた。
見落とすほうが、良い指摘を捨てるより安全という判断。

`--turns` を付けると前のやり取りを踏まえた一続きの会話になる。
付けなければお題ごとに独立した応答。

| 引数 | 既定 | 意味 |
|---|---|---|
| `--times N` | 1 | 同じお題を何回書かせるか |
| `--no-suppress` | 入り | 分岐点での抑圧を切る。読みやすさが落ちる |
| `--fixed-prompt` | 流動 | プロンプトを固定文にする |
| `--prefill 文字列` | `そうですね、` | 書き出し。空にすると相槌なしで始まる |
| `--tokens N` | 200 | 生成する長さの上限 |
| `--raw` | 切る | 途中で切れた文を残す |
| `--seed N` | — | 同じ種なら同じ文章 |
| `--verbose` | — | そのとき選ばれた姿勢と禁止語も出す |

### Python から

```python
from centurion import Centurion

centurion = Centurion()
print(centurion.say("誰かが置いていった傘の話をして"))

# 会話にすると前のやり取りを覚える
for reply in centurion.converse(["朝の匂いについて書いて",
                                 "雨上がりの舗道の匂いについて書いて"]):
    print(reply)
    print(" 姿勢:", " / ".join(reply.stance))

centurion.forget()      # 記憶を捨てる
```

## 原稿を読む

小説の校正・アイデア出しに向けた土台。モデルを使わないので、
GPUが無くても動く。

```bash
python main.py read 原稿.txt --size 6000
```

```
「冒頭プロトタイプ 第五稿」
  4533文字 / 見た目 8835 / 1章 / 103段落 / 218文
    0. (見出しなし)                      4311文字  103段落

3000文字ずつに切ると 2塊
  塊0: 0章 段落0〜70 (2977文字)
  塊1: 0章 段落71〜102 (1587文字、うち重なり1段落)
```

- 文字コードは utf-8 / Shift_JIS / EUC-JP を自動で判別
- 章の見出し(`# 見出し`、`第一章`、`＊` のような区切り)を拾う
- 青空文庫形式は凡例・底本の記録・ルビ・傍点の指定を落とし、題と著者を拾う
- 空行で区切る書き方と、1行1段落の書き方の両方に対応
- 会話文をまたがずに文へ分ける(「行こう。」と言った。→ 2文)

```python
from centurion.manuscript import Manuscript

manuscript = Manuscript.load("原稿.txt")
for chunk in manuscript.chunks(size=6000, overlap=1):
    print(chunk)                    # 塊3: 2章 段落58〜79 (5940文字)
    chunk.text                      # 重なりを含む、モデルに渡す本文
    chunk.body                      # 重なりを除いた、この塊が担当する部分
```

**塊は必ず位置を持ち歩く。** 校正では指摘が原稿のどこを指すかが本体なので、
章・段落の通し番号・原稿全体での文字位置を落とさない。
`manuscript.text[p.start:p.end] == p.text` が全段落で成り立つことを
試験で確かめている(ルビを落とす設定のときは、位置は落とした後の本文に対応)。

## 遠い二つを繋ぐ

発想の中身。ここもモデルを使わない。

Phase 5〜10 で5つの機構を作って、どれも跳躍を生まなかった。
共通していたのは**一本の生成を横へずらそうとしていた**ことである。
跳躍は一点の摂動ではなく二点の関係で、ずらしても繋ぐ相手がいなければ跳ばない。

だから相手を用意する。しかも**原稿の中から**取る。
外から奇抜な要素を持ち込めば提案は奇を衒ったものになるが、
[12]の止まった時計と[87]の折れた傘の骨を繋げと言えば、
提案は作者自身の世界の内側に留まる。
**プロンプトには対を選べない。原稿を全部持っている道具には選べる。**

```python
from centurion.connect import recurrences, distant_pairs
from centurion.manuscript import Manuscript

manuscript = Manuscript.load("原稿.txt")

for item in recurrences(manuscript)[:10]:
    print(item)     # 《反復》「虫干」[15]・[62] (隔たり75%)

for pair in distant_pairs(manuscript, count=5):
    print(pair)     # [23] × [86] (隔たり61% / 重なり0%)
```

**反復** … 稀な語が遠く離れて二度以上使われている箇所。作者がすでに植えた種。
回数が少なければ仕掛け、多ければ作品の背骨として分けて示す。

**遠い対** … 語彙を共有しない遠い二点。まだ架かっていない橋。

繋ぎ方は `build_connection_prompt`(二点に橋を架けさせる)と
`build_chain_prompt`(連想を数歩たどって作品へ戻させる)の二つ。
夢の作業を操作に置き換えた `DREAM_WORK`(圧縮・移動・視覚化・後付け)も
併せて渡せる。

### 効いていることの確かめ方

正解の分かっている作品 — 作者が意図して遠い二点を結んだもの — で試した。
**無作為に対を選ぶ方式は5回試して正解を0件しか拾えなかった**
(候補1165対から6個を引くので当然だった)。
稀な語の反復を手がかりにする方式に変えたところ、
作者が張った伏線が上位に出るようになり、
こちらが正解として数えていなかった接続まで挙がった。

分かっている限界:
- **短い作品には使えない。** 遠い二点が無いので何も出ない。
  実距離の下限を1500文字にしてある — 割合だけで測っていたときは、
  太宰治「I can speak」(1949文字・15段落)で「酔漢」が[8]と[12]に出て
  「隔たり27%」と表示されたが、実際には4段落しか離れておらず、
  同じ場面の同じ人物だった。繋がりはすでに本文にあり、架ける橋がない。
  目安として3000文字を切る原稿では、接続ではなく査読と発想を使う
- **一文字の語は拾えない。** 形態素解析を使っていないため、
  「鴻の鳥」の「鴻」のような一文字の要は落ちる
- **一度きりの語は長編でしか意味を持たない。**
  4500文字の抜粋では221語が該当し、証明・歴史・二日目まで拾ってしまう
- 一般語の除外は、実測で上位に来たものから作った小さな手作りの一覧に頼っている

## 論評と発想

原稿を読ませるための問いと、その組み立ては `centurion/review.py`。

査読と発想は規則が逆を向く。査読では「作品に無いものを言わない」が
幻覚を防ぐ正しい規則になるが、これは**アイデア出しと真っ向から衝突する**。
伴走AIはまだ書かれていないものを語るのが仕事だから。だからモードを分ける。

観点は願望ではなく**操作**として書く。
「独創的な意見を」と頼めば平板な答えが返る
(3Bでの実測では「感覚を書け」50%に対し「名前のある場所か人を置く」78%)。

```python
from centurion.review import build_prompt, check_citations, choose_lenses

lenses = choose_lenses(count=3)          # 群を散らして観点を選ぶ
head, body = build_prompt(chunk, lenses, mode="発想", title=manuscript.title)

# 答えが実在する段落を指しているかを機械で確かめる
real, missing, outside = check_citations(answer, manuscript)
```

段落に番号を振って渡し、指摘を番号で示させる。
多くの査読プロンプトは「引用が実在するか確認せよ」とモデルに自己申告させるが、
番号なら**機械が確かめられる**。

### 実際に論評させる

```bash
python main.py ask 原稿.txt --mode 発想 --api        # その場で論評させる
python main.py ask 原稿.txt --mode 発想 --api --all  # 最初から最後まで
python main.py ask 原稿.txt --mode 接続 --api --dream
```

`--api` は Claude に解かせ、**答えの段落番号の検査まで自動で通す**。
鍵は環境変数 `ANTHROPIC_API_KEY` から読むだけで、この道具は保存も表示もしない。

```bash
setx ANTHROPIC_API_KEY "自分の鍵"      # Windows。設定後に端末を開き直す
```

`--all` は塊ごとに観点を入れ替える。全部の塊に同じ観点を当てると
同じ角度の指摘が並ぶだけになるため(Phase 9 の処方)。

`--run` にすると手元(か Colab)のモデルで解く。無料だが、
**3B級では論評の質が出ない**。

### 鍵を使わない道

```bash
python main.py read 原稿.txt                        # 塊と反復の一覧

```

### 答えを検査する

`--api` / `--run` のときは自動で走る。貼って答えを得た場合は `check` で。

```bash
python main.py check 答え.txt 原稿.txt --out 添削.txt
```

三種類の誤りを見つける。

| 検査 | 見つかるもの |
|---|---|
| 段落番号の実在 | 存在しない番号への指摘 |
| 渡した範囲(`--chunk N`) | 読ませていない段落への言及 |
| **引用と本文の照合** | **番号と中身が食い違う指摘、本文に無い文の引用** |

三つ目が要る理由。Qwen2.5-3B に104段落の原稿を読ませたところ、
段落番号は**18件すべて実在して検査は素通り**した。ところが引用を突き合わせると、
**14件中8件が別の段落の中身**で、**うち3件は本文にどこにも無い文**だった。

```
× [58] 引用は [57] の中身: エーマートの前を通った。半分…
× [59] 本文に無い文を引用している: 帰る途中、エーマートの冷蔵庫…
```

「引用が実在するか確認せよ」とモデルに自己申告させても効かない。
申告する当人が取り違えているため。

### 添削ファイル

`--out 添削.txt` で、本文の各段落の下にその段落あての指摘を貼ったファイルを書く。
照合に落ちた指摘には `×` が付くので、信じてよいものと捨てるものが分かれる。

```
[58] アパートに帰り、電気もつけずに、私は部屋の真ん中に立っていた。
    × - **段落 [58]**: 「エーマートの前を通った。半分切れた看板が…」

[59] 座ればいいのに、と自分でも思う。布団はそこにある。座椅子もある。
    × - **段落 [59]**: 「帰る途中、エーマートの冷蔵庫の扉を開けると…」
```

## 分かっている限界

**目的の後半は達成していない。** 「文章を保つ」は抑圧で達成したが、
「発想の飛躍」は3つの機構を作って測って、いずれも読み手には届かなかった。
いま出てくるのは、読みやすく、常套からわずかに外れた文章であって、
飛躍ではない。

**随筆調に寄る。** 実測112件を数えるとこうなっている。

| | |
|---|---|
| 読み手に語りかける | 112/112 (100%) |
| 名前のある人や場所を含む | 2/112 (2%) |
| 過去の出来事を2文以上語る | 32/112 (29%) |
| 一文目が「Xは〜です」型の一般論 | 47/112 (42%) |

人格には「物語だけを愛する」と書いてあるのに、7割が出来事を語らない。
原因は書き出しの「そうですね、」だと見ている — 相槌のあとに文法的に
自然に続くのは同意・意見・一般化であって、場面ではない。
ただしこれは**未検証**なので、既定は評価時と同じ相槌のままにしてある。
`--prefill` で試せる。

**流動プロンプトの優位は確定していない。** p=0.108 で、有意水準には
届いていない。戻すなら `--fixed-prompt`。
